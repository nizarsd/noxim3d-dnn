# Packing (c, r, s) sweep — all distinct points

Generated by `tools/packing_rs_sweep.py`. Byte columns come from
`stage2_core.build_flows()` itself, so each workload's **(8, 1, 8)** row
reproduces its shipped `flows.csv` byte-for-byte — that is the correctness gate
on the whole grid.

Setup: 128x128 crossbars, INT8 activations, INT32 partial sums, mesh 6x6x3 = 108
nodes. `c = r * s`; `r` = input grouping (sets reduce traffic), `s` = output
grouping (sets scatter traffic).

**`r > 1` is not reachable by the generator today** — it trips the
`R >= base_R` assert at `stage2_core.py:106`. The script patches `Layer.__init__`
in memory only; the repo file is untouched. Every row except the `r = 1` column
is therefore arithmetic, not something the converter can currently emit.

**Two classes of misleading row:**
- `Reduce = 0` (VGG 32/32/1, DeiT-S 16/16/1, 32/16/2, 32/32/1) — every reduction
  fits inside one tile, nothing crosses the NoC, the phenomenon disappears.
- Low-traffic points are mostly-idle meshes: ResNet (32,4,8) uses 28 tiles of
  108, VGG (32,16,2) 40, DeiT-S (32,4,8) 33.

**Structure:** reduce depends only on `r`, scatter only on `s` — read down any
reduce column at fixed `r` and it is identical across every `c`.
